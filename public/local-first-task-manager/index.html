Local-first

A local-first task manager, and what that actually means

"Local-first" gets used as decoration. Here it means something specific: the only copy of your task list is on your machine, the app works without a network request, and you can leave with all of your data at any time.

Open Adwait — free Runs entirely in the browser.

What "local-first" means in Adwait

There is no backend. Adwait is a static application; once the page has loaded, nothing it does requires a server. Tasks, buckets, completed sessions, and the active timer are written to localStorage under a single key (adwait:v1).

That has three practical consequences:

  • No account. There's no user record to create, so there's no login, password, or verification email.
  • No data plane. Your tasks aren't uploaded, mirrored, or analysed. There is no "our servers" for them to sit on.
  • No lock-in. Export writes a plain JSON file with every task, bucket, and session. Import reads it back.

What a server would have given you

Being honest about the trade: a cloud task manager gives you automatic sync across devices, a mobile app with push reminders, sharing, and the guarantee that a dead laptop doesn't lose your list. Adwait gives you none of that by design.

For a single person working on one machine, those features are often overhead — a login screen, a sync conflict, a subscription. For someone coordinating a team or living on a phone, they're essential. The point isn't that local-first is universally better; it's that it should be a choice rather than the only option on the shelf.

If you're going to rely on it

Export a backup on a schedule you'd actually keep — end of the week is usually enough. The export is a single JSON file named adwait-backup-YYYY-MM-DD.json, readable in any text editor, and importable on any browser. If you store it in a synced folder, you've effectively built the sync you were missing.

How corruption is handled

If the saved data can't be parsed — a half-written write, an extension interfering — Adwait doesn't crash into a blank screen. It moves the unreadable payload aside under a adwait:corrupt:<timestamp> key and starts clean, so the broken data is still recoverable by hand.
